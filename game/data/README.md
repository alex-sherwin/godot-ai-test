# `game/data` — the shipped disc data

Everything here is generated by `tools/aero/bake.py`. Do not hand-edit it;
edit `tools/aero/roster.py` (published facts) or `tools/aero/coefficients.py`
(the model) and re-run the bake.

```
game/data/
  discs.json        the roster: 14 real discs, published ratings + geometry
  aero/<id>.json    one baked coefficient table per disc
```

Regenerate and verify:

```bash
python -m tools.aero.bake            # rewrite everything
python -m tools.aero.bake --check    # assert the committed files are current
python -m pytest tools/aero          # 108 tests + 1 recorded miss
```

## Schema

### `aero/<id>.json` (CONTRACT §3)

| field | meaning |
|---|---|
| `schema` | `1` |
| `id` | matches the filename and the roster entry's `aero` field |
| `source` | `giljarhus2022:<case>` for measured, `derived:affine(<base case>)` otherwise |
| `source_note` | prose describing exactly what was done to produce this table |
| `aero_provenance` | `"measured"` \| `"derived"` — **the UI must surface this** |
| `alpha_deg` | 361 points, strictly ascending, uniform 0.5° over [-90, 90] |
| `cl`, `cd`, `cm` | same length as `alpha_deg` |
| `damping` | `c_mq`, `c_rp`, `c_nr` plus a `provenance` sub-object |
| `anchors` | `CM(0°)`, `CM(10°)`, and the flight numbers recovered from them |
| `interpolation` | reminder that the runtime should interpolate linearly |

The grid is already PCHIP-resampled, so the runtime does plain linear
interpolation with negligible error. **PCHIP, not natural cubic splines**: the
measured stations are unevenly spaced (2° through the linear range, 10° in the
wings), and a natural spline overshoots between them. On `CM` near α = 0 an
overshoot is a *sign change*, which is to say fabricated turn or fade.
`test_bake.py::test_a_natural_cubic_spline_would_have_overshot` measures the
overshoot a natural spline actually produces on these knots, and asserts PCHIP
produces none.

### `discs.json`

Each entry carries `flight_numbers`, the eight CONTRACT §2 `geometry`
parameters, the `derived` quantities (`area_m2`, `parting_ratio`, `nose_ratio`,
`I_zz`, `I_xy`, `height_m`, `density_kg_m3`), `aero`/`aero_provenance`, and a
`geometry_provenance` block that labels **every geometry field individually**
with where its number came from.

## Provenance: what is measured and what is not

Real aerodynamic data exists for exactly four disc golf discs. Everything else
is derived from those four.

### The four measured discs

| roster disc | CFD case | link confidence |
|---|---|---|
| Innova Firebird | `cd1` | **exact** — the upstream file's header names the mould |
| Innova Teebird | `fd2` | **exact** — same |
| Innova Roadrunner | `cd5` | **exact** — same |
| Innova Destroyer | `dd2` | **class match only** — see below |

Source: Giljarhus, Kristiansen, Tutkun & Oggiano, *Aerodynamic characteristics
of a golf disc*, Sports Engineering 25:24 (2022), CFD run on scanned real disc
geometry. Data obtained from the authors' reference implementation
<https://github.com/kegiljarhus/shotshaper> (GPL-3.0; the licence text and full
attribution are in `tools/aero/reference/`). Their tables are resampled onto the
shared grid and **otherwise unmodified** — no smoothing, no refitting.

> **The Destroyer is the weakest of the four claims.** The `dd2` data file
> carries no header naming a commercial mould, unlike the other three. It is a
> 12/5/-1/3-class distance driver, which is the Destroyer's class, but the paper
> does not say the scanned disc was a Destroyer. The roster records this as
> `measured_link.confidence = "class_match"` with the reasoning attached. If the
> UI ever renders "measured" as an authority claim, this disc deserves a
> footnote.

Two quirks in the upstream data, preserved rather than cleaned:

* `cd1` and `fd2` share their α ≤ -15° and α ≥ 25° wings — upstream copied them.
  Agreement between those two discs at high α therefore carries no information.
* `fd2` ships an older, commented-out set of values for -10° ≤ α ≤ 20°. We take
  the live ones.

### The ten derived discs

Aviar, Zone, Roc, Buzzz, Leopard, FD, River, Undertaker, Wraith, Boss.

Method: pick the nearest measured disc by rating distance, then affine-map its
`CM` curve, `CM' = a·CM + b` with `a > 0`, so it passes through two anchors
predicted from this disc's geometry. `CL` and `CD` are scaled by single
geometry-driven factors. Outside |α| > 30° the correction tapers back to the
measured curve and is gone by |α| = 60°, because the affine offset would
otherwise leave `CM(±90°) ≠ 0`, which edge-on symmetry forbids.

**The shape is measured. Where the disc sits within that family is modelled.**

## What we can support, and what we cannot

### The two anchor regressions — n = 4

```
turn = 296.87 · CM(0°)  + 3.314    R² = 0.890
fade = 182.76 · CM(10°) − 4.221    R² = 0.908
```

Reproduced exactly from the cached CFD data by `test_coefficients.py`. R² of
0.89 on **four points** is four points. Two free parameters fitted to four
observations leaves two degrees of freedom. These are the best relations
available and they are still not a validated model.

### Speed from rim width — the one solid link, n = 14

```
speed = 703.1 · rim_width_m − 4.453    R² = 0.948
```

Fitted over the 14 roster discs using PDGA-published rim widths and
manufacturer speed ratings. The literature reports R² = 0.96 over 43 discs; we
do not have that dataset, so this is our own fit and this is our own R². Worst
prediction error across the roster is 1.02 rating points (Buzzz).

### Drag from rim width — weak, applied anyway, clamped

```
CD(0°) = −1.321 · rim_width_m + 0.0715    R² = 0.38, n = 4
```

R² = 0.38 on four points is barely a trend. It is applied because the direction
(wider, sharper rim → lower parasite drag) is not in doubt, and the resulting
scale factor is clamped to [0.80, 1.60] so that a putter — extrapolated well
outside the fitted 17–22 mm range — cannot run away.

### Glide — **not fitted, and not fittable from this data**

Three of the four CFD discs are rated glide 5 and one glide 3. That is one
contrast. Peak L/D is **4.149** for the glide-3 disc against **4.151**, **4.186**
and **4.509** for the glide-5 discs: nominally in the right order, but 0.05%
below the nearest glide-5 disc while the glide-5 discs are spread over 8.6%
among *themselves*. A one-point contrast buried an order of magnitude inside the
within-group scatter is not a signal.

So the glide → `CL` scaling is an **author-chosen heuristic**: ±3.5% of `CL` per
glide point off the roster mean, clamped at ±15%. It exists so the rating does
something rather than nothing. `coefficients.GLIDE_MODEL_IS_FITTED` is `False`
and `test_coefficients.py` asserts the lack of separation that justifies it.

### `parting_line_m` and `rim_thickness_m` — inferred, not measured

The PDGA publishes diameter, height, rim depth, rim thickness and inside rim
diameter. **Nobody publishes the parting-line height or the axial thickness of
the rim wing**, and those are precisely the two parameters that drive stability.

So the roster *infers* them: it inverts the geometry→`CM` model to find the pair
that reproduces the disc's published turn and fade. They are model output
wearing the shape of a measurement, marked `inferred_from_flight_numbers` in
`geometry_provenance`. Every inferred value lands in a manufacturable range
(parting lines 3.1–8.5 mm, noses 2.5–10.7 mm, parting ratios 0.26–0.71), which
is a sanity check, not a validation.

A consequence worth being explicit about: the geometry→`CM` model is a
**calibration, not a regression**. There is no dataset of parting-line heights
to regress against. Its *signs and relative magnitudes* come from the published
finding that parting-line ratio dominates both turn and fade; its slopes were
chosen so the roster maps onto plausible profiles. **It has no R², and none is
quoted.** The round-trip in the bake report (`published → geometry → CM →
published`) is exact for derived discs *by construction*: it verifies the
inversion, not the model.

The measured discs show the real residual, because they use raw CFD data rather
than a fitted inverse:

| disc | published turn/fade | recovered |
|---|---|---|
| Teebird | 0 / 2 | -0.01 / 2.07 |
| Firebird | 0 / 4 | 0.38 / 4.20 |
| Roadrunner | -4 / 1 | -3.48 / 1.30 |
| Destroyer | -1 / 3 | -1.88 / 2.43 |

That spread — up to 0.9 rating points — is the honest accuracy of the n = 4
regressions.

### Mass and geometry sourcing

`mass_kg` is an **estimated** typical throwing weight, not a published figure;
real discs of a mould ship across a weight range. The bake asserts it never
exceeds the PDGA maximum for that mould.

`dome_height_m` is derived from the published overall height minus rim depth
minus an assumed 1.8 mm flight plate.

PDGA records were retrieved in 2026-08 via web search (pdga.com is not directly
reachable from the build sandbox) and every one was cross-checked against
`inside rim diameter == diameter − 2 × rim thickness`. Four (Zone, FD, River,
Undertaker) disagree by exactly 0.1 cm, which is rounding in the published
table; the bake reports them and uses diameter and rim thickness as primary.

Three moulds — Roc and Buzzz at 21.7 cm, River at 21.5 cm — have published
diameters above the 21.0–21.3 cm band CONTRACT §2 calls typical. **Those are the
published measurements and they are shipped unmodified** rather than trimmed to
fit a comment.

### Damping — Ultimate-disc numbers, because nothing else exists

`c_mq = -0.0144` and `c_rp = -0.0125` are Hummel's (2003) long-flight fit to an
**Ultimate** disc, used unchanged. No disc-golf-specific measurement of pitch or
roll damping exists in the literature.

`c_nr` is **recalibrated and deliberately not Hummel's number**, and this needs
saying plainly. CONTRACT §4 requires the spin-down moment to carry the same
`0.5·ρ·V²·A·d` scaling as the other two moments — Hummel's published MATLAB
omits the `A·d` factor, a bug that has been widely copied. But her *numeric*
`CNr = -3.41e-5` was fitted to her own unscaled form. Dropped into

```
M_spin = 0.5·ρ·V²·A·d · c_nr · (spin·d / 2V)
```

it yields roughly **0.2%** spin loss over a drive, against the 10–20% that is
actually observed. The value and the equation are incompatible; shipping both
unchanged would be self-consistent only on paper. We therefore ship
`c_nr = -3.0e-3`, calibrated to that equation, and keep Hummel's raw number in
`damping.provenance.c_nr_hummel_2003_raw` so nothing is hidden. The reference
integrator measures **12.1%** spin loss on the CONTRACT §5 distance drive.

## How the shipped data actually flies

Numbers from `python -m tools.aero.validate` (sea level, 1.225 kg/m³, no wind,
RK4 at 1/240 s, launch height 1.4 m). Full trajectories are dumped to
`tools/aero/validation/`.

| throw | dist | lateral | max right | peak | time | spin lost |
|---|---|---|---|---|---|---|
| Destroyer, 27 m/s, 25 rev/s, 8° hyzer | **115.8 m** | +5.7 m | 13.8 m | 12.0 m | 9.37 s | 12.1% |
| Aviar, 13 m/s, 10 rev/s | 21.0 m | -1.7 m | 0.0 m | 1.7 m | 1.98 s | 2.8% |
| Roadrunner, 25 m/s flat | 89.1 m | +31.2 m | 31.2 m | 7.0 m | 6.09 s | 9.5% |
| Firebird, 25 m/s, 5° hyzer | 83.4 m | -26.2 m | 0.0 m | 9.2 m | 6.17 s | 9.2% |
| Teebird, 23 m/s, 3° hyzer | 80.6 m | -18.9 m | 0.0 m | 6.8 m | 6.11 s | 10.0% |
| Buzzz, 20 m/s flat | 59.0 m | -4.7 m | 0.6 m | 4.0 m | 4.94 s | 8.3% |
| Destroyer RHFH (mirror) | 115.8 m | -5.7 m | 0.3 m | 12.0 m | 9.37 s | 12.1% |

Against the CONTRACT §5 sanity targets:

* **12/5/-1/3 at ~27 m/s, ~25 rev/s, small hyzer → 105–130 m with an early right
  turn and a left fade finish.** Met: 115.8 m, turns out to +13.8 m then fades
  back to +5.7 m. The sign flip lives in `CM(α)` — it crosses zero at α ≈ 3.5°
  partway through the flight — not in spin decay.
* **RHFH mirrors RHBH exactly.** Met, to 1e-6.
* **More spin → less turn and less fade.** Met *on the attitude*, which is what
  `Ω = τ/(I_zz·ω)` actually says: disc tilt at t = 2 s falls 32.3° → 23.7° →
  18.7° → 15.5° → 13.2° as spin goes 15 → 35 rev/s. Landing drift is **not**
  monotone (24.8 → 35.3 → 46.4 → 51.5 → 47.3 m), because more spin also keeps
  the disc flat, which keeps it airborne longer, which gives the residual bank
  more time to work. Both are reported; quoting only the second would make the
  model look broken when it is not.
* **Understable disc thrown flat and fast turns over.** Partly met: the
  Roadrunner at 25 m/s flat runs 31 m right and never fades back, but it only
  reaches 23° of tilt, so it does not reach a roller attitude. See the
  precession note below.
* **2/3/0/1 putter at ~13 m/s → 40–60 m.** **Not met: we get 21.0 m.** The shape
  is right (nearly straight, gentle left fade) but the distance is not. 13 m/s
  is roughly a 10 m putt; this model needs ~18 m/s to reach the band (17 m/s →
  38.4 m, 18 m/s → 43.4 m, 20 m/s → 53.9 m). The test for this target exists and
  is marked `xfail(strict=True)` rather than loosened.

### Cross-validation against `shotshaper`

The reference implementation from the same authors as the CFD dataset. With its
precession law substituted for ours, our integrator reproduces it closely, which
verifies everything in `validate.py` *except* that one constant:

| throw | shotshaper | ours, matched precession | ours, Euler precession |
|---|---|---|---|
| their example (24.2 m/s, 15.5°, 14.7° roll) | 82.1 m, 6.87 s, 11.5 m peak | 81.7 m, 6.73 s, 11.5 m | 76.5 m, 6.88 s, 12.1 m |
| flat, 27 m/s, 25 rev/s | 75.0 m, 4.13 s | 72.1 m, 3.75 s | 108.7 m, 7.28 s |

### The precession disagreement, stated plainly

`shotshaper` rolls at `−M/(ω(I_xy − I_z))`. CONTRACT §4 mandates
`−M/(I_zz·ω)`, and that is what we implement. The contract is right on the
derivation: the `(I_a − I_t)` form comes from setting `ṗ = q̇ = 0` in the Euler
equations written in the *spinning* body frame, where the transverse rate
components are not constant during steady precession. Done in the non-spinning
frame the `I_xy` terms cancel. For a flat disc `I_xy ≈ I_zz/2`, so the two
differ by a factor of ~2.

But the honest consequence: **their (incorrect) law matches their measured
throws better than the correct one does.** Half the precession means half the
fade, so our discs hold their turn longer and land wider — the flat Destroyer
runs 46 m right where theirs runs 25 m, and our flight times are long (9.4 s for
a 116 m drive, against a real ~6 s). We follow the contract and do not tune
around it. Two candidate explanations, neither verified: the CFD pitching moment
may be too strong by roughly that factor, or the missing spin-induced roll
moment — which the CFD dataset does not contain **at all**, and which Potts &
Crowther measured as `CRr` — supplies the balance. Resolving this is the single
highest-value thing anyone could do to this model.

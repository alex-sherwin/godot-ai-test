# Validation fixtures

Generated by `python -m tools.aero.validate --dump`.

Each named-throw file is one throw: the disc, the throw parameters, the
environment, the integrator settings, a summary, and the full per-sample
trajectory (position, velocity, disc normal, quaternion, spin, angle of attack
and the three coefficients actually used). Sampling is every 12 substeps at
dt = 1/240, i.e. 20 Hz.

Track B should reproduce these with `DiscFlightSim` using the same baked table
from `game/data/aero/`.

Sign conventions are CONTRACT §1. `hyzer_angle_rad` is positive-is-left-bank for
a RHBH throw (§4 v2 / §5).

**These fixtures were regenerated for the CONTRACT §4 v2 precession law**
(`dn/dt = -M_perp / ((I_zz - I_xy) * spin)`). Anything generated against the v1
law is stale by roughly a factor of two in fade and must not be compared
against.

Sweeps rather than single throws:

* `hyzer_sweep.json` — release-angle sensitivity for the §5 distance target.
  Published because that target is genuinely sensitive to the release: at 27 m/s
  a 12-speed is understable, so the throw is a hyzer-flip.
* `spin_sensitivity.json` — spin response, plus the putter speed sweep.
* `shotshaper_cross_check.json` — our integrator against the published
  reference implementation, and against the superseded v1 precession law.
